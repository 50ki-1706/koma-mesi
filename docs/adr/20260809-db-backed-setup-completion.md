# DB による初期設定完了判定

## ステータス
Accepted

## 背景
これまで初期設定の完了状態を、`koma-mesi:initial-setup-completed:{userId}`
という localStorage のキーで管理していた。しかし localStorage はブラウザごとに
分離され、削除される可能性があり、端末間でも状態を共有できないため、ログイン
ユーザーの設定状態を正しく追跡できなかった。また、住所や昼食設定が状態とは別に
扱われ、データベースに保存されていなかった。

## 判断
初期設定完了の判定には `user_preferences` テーブルのユーザー単位のレコードの
存在を用いる。初期設定フォーム送信時にレコードを作成し、住所は既存の
`campusAddress`（緯度・経度は `campusLatitude`、`campusLongitude`）へ保存する。
昼食時間帯と曜日も同じレコードへ保存し、曜日は月曜日から日曜日までの決定的な
順序で並べたカンマ区切りのテキストとして、新設した `lunch_start_time`、
`lunch_end_time`、`lunch_days` カラムに格納する。

既存レコードで昼食関連カラムが null の場合も、レコード自体が存在すれば初期設定
完了として扱う。これにより、既存データを未完了へ戻さず後方互換性を保つ。

## 影響
完了状態と初期設定データがユーザーに紐づいて DB で一元管理されるため、localStorage
の消去やブラウザ・端末の変更に影響されず、端末間で設定を利用できる。引き換えに、
完了判定は同期的な localStorage 読み取りではなくネットワークを伴う DB 問い合わせと
なり、読み込み遅延や通信失敗を考慮する必要がある。また、曜日の保存形式は単純な
テキストのため、読み書き時に順序と区切り形式を一貫させる必要がある。
