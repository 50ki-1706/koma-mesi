# ADR: 飲食店レコメンド機能のデータモデル

- **Status:** Accepted
- **Date:** 2026-08-07

## Context

ログイン後、ジャンルごとにおすすめの飲食店を1件ずつ表示するページ（`/recommendations`）を追加する。要件は以下の通り:

- 飲食店（Recommendation）はジャンルごとに複数の候補を持ちうるが、UI では各ジャンルにつき常に1件だけを表示する
- 表示項目には、大学から店までの距離（道のり）と時間が含まれる
- 距離・時間の算出方法（都度Google Maps Directions APIで計算するか、事前に保存した値を使うか）を決める必要がある

## Decision

### ジャンルとレコメンドは 1 : 多、表示対象は `isFeatured` フラグで選ぶ

`genre` テーブルと `recommendation` テーブルを新設し、`recommendation.genre_id` で1ジャンルに複数の店を紐づけられるようにする。ただし現状のUIは各ジャンルにつき1件のみ表示するため、`recommendation.is_featured` (boolean) を追加し、`isFeatured = true` の行だけを表示対象として取得する。

この設計にした理由:

- 将来的にジャンルごとに複数候補を持たせて選定ロジックを変える可能性があるため、テーブル自体は 1 : 多 の関係で作り、表示対象の選定は独立したフラグで制御できるようにした
- ジャンルと店を 1 : 1 に固定してしまうと、候補の入れ替えのたびにレコードの作り直しが必要になり、将来の拡張コストが高くなる

### 距離・時間は `recommendation` テーブルに保存した静的な値を表示する

`distance_meters`（大学から店までの距離）と `duration_minutes`（大学から店までの時間）を `recommendation` テーブルのカラムとして保存し、ページ表示時はこの値をそのまま表示する。Google Maps Directions API を使った動的な算出は行わない。

この設計にした理由:

- 距離・時間はデータ登録時（または定期バッチ）に一度計算すればよく、閲覧のたびに外部APIを呼ぶ必要がない
- `feature/map-page` ブランチで実装した Directions API 連携（`useDirectionsRoute` など）は、本機能のブランチ（PR #4 ベース）には含まれておらず、今回は依存させない判断とした
- 将来、経路表示など動的な地図連携が必要になった場合は、別途 `feature/map-page` の機能と統合を検討する

## Consequences

- レコメンドデータの登録・更新時に、距離・時間を計算して保存する仕組み（手動 or バッチ）が別途必要になる。今回のスコープには含まない
- `isFeatured` を切り替えるだけで表示対象の店を差し替えられるため、運用上の柔軟性が高い
- 複数ジャンルで同時に `isFeatured = true` の店が0件・複数件になる不整合はアプリケーション側で防止していない。今後、管理画面や登録フローを作る際にバリデーションを追加する必要がある
- 将来 Google Maps Directions API と連携する場合、距離・時間カラムの更新ロジックを別途設計する必要がある
